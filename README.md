# Капсула времени

Сайт на Maven, Java Servlets, JSP/JSTL и PostgreSQL. Пользователь публикует фото с заметкой и датой открытия. До этой даты в ленте видны только заголовок и таймер. После даты открытые капсулы видны всем вошедшим пользователям. Содержимое и изображение дополнительно проверяются на сервере при каждом запросе.

## Что есть в MVP

- регистрация, вход, выход и роли USER / ADMIN;
- CRUD капсул для владельца;
- категории с полным CRUD в админке;
- теги с отношением многие-ко-многим к капсулам;
- хранение файлов вне web-каталога, выдача изображения через сервлет;
- JSP с JSTL и JSP-фрагментами;
- AJAX-запрос за содержимым после истечения таймера;
- проверки форм, PRG после успешной отправки, защита создания капсул от повторной отправки через UUID-ключ и уникальный индекс в PostgreSQL, PreparedStatement в JDBC.

## Архитектура и связи

- Контроллеры: `web.servlet`; бизнес-логика: `service`; модели: `model`; JDBC-контракты и реализации: `repository` и `repository.jdbc`.
- `AppContextListener` создаёт репозитории и сервисы один раз при запуске приложения.
- Фильтры проверяют сессию, роль администратора, CSRF-токен и UTF-8.
- Сущности: пользователь, капсула, категория, тег и файл. У капсулы три внешних ключа: владелец, категория и фото.
- Пользователь имеет много капсул. Капсула и тег связаны многие-ко-многим через `capsule_tags`.
- Капсулы открыты другим вошедшим пользователям после даты открытия; до неё отдаются только заголовок и таймер.

## Локальный запуск

1. Нужны JDK 17, Maven (можно использовать Maven из IntelliJ IDEA), PostgreSQL и Tomcat 9.
2. Запустить локальный сервер PostgreSQL и создать базу `time_capsule`.
3. Открыть `database/schema.sql` в pgAdmin, выбрать базу `time_capsule` и выполнить скрипт.
   Если база уже создана по прежней версии схемы, вместо повторного запуска `schema.sql` выполни `database/add_capsule_request_key.sql`.
4. Указать `DB_PASSWORD` в переменных окружения конфигурации Tomcat в IntelliJ. `DB_URL` и `DB_USER` можно переопределить там же. Значение берётся сначала из системного свойства Java (`timecapsule.db.*`), затем из переменной окружения (`DB_*`), потом из `WEB-INF/web.xml` и в конце из встроенного локального значения по умолчанию. Не сохраняй реальный пароль в Git.
5. Открыть папку проекта в IntelliJ, дождаться импорта Maven-зависимостей и выбрать JDK 17 для проекта.
6. Добавить Tomcat 9, развернуть артефакт `time-capsule:war exploded` и запустить.
7. Создать аккаунт через форму регистрации.
8. Назначить ему роль администратора запросом из `database/promote-admin.sql`, заменив адрес на свой.

Загруженные изображения по умолчанию хранятся в системной временной папке `time-capsule-uploads`. Путь можно задать системным свойством Java `timecapsule.uploadDir`.

## Настройка базы

Для подключения используются параметры `timecapsule.db.url`, `timecapsule.db.user`, `timecapsule.db.password` (системные свойства Java) или `DB_URL`, `DB_USER`, `DB_PASSWORD` (переменные окружения). Если они не заданы, приложение использует значения из `WEB-INF/web.xml`, затем локальные значения по умолчанию. Значения в файле — примеры; не публикуй реальные пароли в GitHub.
